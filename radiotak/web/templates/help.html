Getting started

▼

After install, open the console at https://<pi-ip>:5001 and complete first-run setup if prompted.

Typical flow:

1. Marketplace → install SDR Location Gateway
2. SDR → discover dongle, add radio system control-channel frequencies (MHz), start decoder
3. Units → approve observed radios for TAK forwarding
4. TAK Servers → enroll certificate and select channels

Use the Console dashboard to confirm hearing activity (messages/min, CC lock) and the mini-map for live positions.

TAK enrollment

▼

Each TAK server supports username/password enrollment against Marti TLS (default port 8446), PKCS#12 import, or PEM cert/key upload. Uncheck Verify TLS if the enrollment certificate is self-signed.

After enrollment, RadioTAK queries Marti on port 8443 for groups/channels. Select active channels on the server detail page. Channel membership is pushed to TAK Server after the CoT stream is connected — a 400 from /groups/activebits while disconnected is expected and is not a failed enrollment.

CoT streaming uses TLS port 8089 by default. When connected, RadioTAK publishes a presence user with the gateway callsign so it appears in the TAK Server client dashboard. Radio detections are named map markers and are not ATAK contacts unless you choose a friendly-unit CoT type. Use Test on the TAK list to queue a test marker.

Certificate expiry warnings appear at 30 / 14 / 7 days. Re-enroll before expiry to avoid forwarding interruption.

Units allowlist

▼

Radios heard by the decoder appear under Observed. Only Approved units are forwarded to TAK unless Settings → Forwarding allows unknown radios.

Approve a unit to add it to the allowlist, then edit callsign, CoT type, team, and role. Per-unit settings override TAK server defaults.

Each forwarded radio is published as a named marker (callsign or radio ID). By default that marker is not an ATAK contact. Radio locations stay on the map until they stale — default 20 minutes, configurable under Settings → Forwarding.

Default policy is deny for unknown radios — this keeps your TAK map free of unauthorized subscribers.

SDR

▼

SDRTrunk runs under Xvfb on the Pi. Discover USB dongles, configure tuner gain/PPM/bias-tee, then add radio systems with control-channel frequencies.

For trunked P25/DMR enter the control channel (CC) in MHz — not random voice channels. Use RadioReference or agency programming as reference.

Use Listen / Stop on each radio system to include it in the decoder playlist. Green means that system has a dongle. Yellow means it is on but waiting for another SDR. One RTL-SDR typically runs one trunked system at a time.

Write playlist & restart applies frequency changes. Start/Stop controls the decoder service directly.

Spectrum / waterfall

▼

The Console waterfall displays DFT frames exported from SDRTrunk over a local TCP feed (default 127.0.0.1:29501).

Cyan vertical lines mark configured control-channel frequencies. Use the waterfall to verify the decoder is tuned to the correct spectrum segment.

GPS / Live Events use a different port (127.0.0.1:29500). A moving waterfall does not mean units will appear — that requires a radio to send lat/lon through the geo exporter.

The Decoder build card on the SDR page shows which SDRTrunk is installed. A stock DSheirer build has no exporters, so the canvas stays black and no GPS arrives even while it decodes audio. Press Upgrade decoder there (or wait — RadioTAK re-runs the module installer automatically about 20 s after it starts when the build is behind, and after System → Update).

Below the canvas, Spectrum feed and GPS feed report whether the exporters are connected and how many frames / GPS lines have arrived. SDRTrunk takes about a minute to start on a Raspberry Pi; the spectrum exporter connects only after the tuner is shown in its spectral display.

Tailscale

▼

Join this appliance to your tailnet for remote HTTPS access without exposing port 5001 to the public internet.

Create an auth key in the Tailscale admin console (Settings → Keys), then paste it on the Tailscale page with your preferred hostname.

Enable Tailscale SSH for headless recovery. The hostname also appears as the banner subtitle when set.

Updates / recovery (CLI)

▼

System page → Update Now pulls the configured git branch and shows a live log. The console goes offline during the restart; leave the tab open and it will wait until RadioTAK comes back. Use Settings to switch between main and dev.

If git reports insufficient permission for .git/objects, files were left owned by root from a previous sudo update. The console now repairs that automatically. Recovery from SSH:

sudo radiotak status
sudo radiotak logs
sudo radiotak update
sudo radiotak reset-password
sudo radiotak diagnostics

Download diagnostics from System for support bundles. Purge removes old logs and observations per retention settings.

Marker appearance

▼

Each TAK server has default marker settings: radio callsign, CoT type, iconset path, color, how, circular error (CE), and optional RadioTAK user position.

Unit-level edits override server defaults. Default radio CoT type is a-n-G (named marker, not a contact). Colors use #RRGGBB hex and appear on ATAK/iTAK and the RadioTAK map.

Iconset path format: uuid:Group/name — inspect an existing marker in CloudTAK/ATAK for reference.
